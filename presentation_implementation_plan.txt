Context

Creating a professional presentation for the Samsung Innovation Campus "Technology of Mobile Development" program to showcase the CAMPUS project - a comprehensive mobile application for managing pedagogical squads (отряды), children, events, and notifications in summer camp settings.

Goal: Present a technically accurate, visually compelling demonstration of all implemented features, technologies used, and architectural approaches.

Audience: Samsung evaluators, mentors, and peers - technical depth appropriate for mobile development professionals.

---

Presentation Format: Interactive HTML Artifact

- Self-contained HTML file with embedded Mermaid.js for diagrams
- Responsive design with dark/light theme support
- Navigation controls (prev/next, slide counter)
- Speaker notes for each slide
- Samsung-branded aesthetic (professional, corporate-ready)

Slide 6: API Design — RESTful Architecture

- Base Path: /api/v1
- 6 доменных роутеров:
  a. /auth — Авторизация и регистрация
  b. /squads — Управление отрядами (только senior+)
  c. /children — CRUD детей + система тегов
  d. /notifications — Система уведомлений
  e. /events — Журнал мероприятий и посещаемость
  f. /users — Профиль и назначение на отряды
- Цепочка middleware: authMiddleware → logger.middleware → verifySeniorCounselourRights (где нужно)
- OpenAPI 2.0 Spec: 972 строки, встроенная бизнес-логика, 50+ эндпоинтов

    API->>API: bcrypt.compare(password, hash)
    alt Valid credentials
        API->>API: jwt.sign({userId, role}, JWT_SECRET, {expiresIn: '7d'})
        API-->>Client: 200 OK {token}
        Client->>Client: Сохранить токен в SharedPreferences
    else Invalid
        API-->>Client: 401 Unauthorized
    end

    Note over Client,API: Последующие запросы
    Client->>API: GET /api/v1/users/profile\nAuthorization: Bearer <token>
    API->>API: jwt.verify(token, JWT_SECRET)
    alt Valid token
        API->>DB: SELECT * FROM users WHERE id=?
        API-->>Client: 200 OK {profile}
    else Invalid/Expired
        API-->>Client: 401 Unauthorized
    end

Slide 11: Ключевая фича — Управление отрядом и детьми (Отряд)

Реализовано: ✅ Полный CRUD для детей, поиск, редактирование заметок, отображение тегов
- SquadFragment: RecyclerView с фильтром поиска, карточки детей (ФИО, возраст, контакты родителей, теги, заметки)
- Диалог редактирования заметок: DataEditWaitButton (активен только при наличии изменений)
- Кэширование: SharedPreferences хранит squadId, squadTitle, список детей для офлайн-доступа
- API Эндпоинты:
  - GET /users/squad → проверка назначения на отряд
  - GET /squads/{squadId}/children → получение детей с тегами
  - PUT /children/{id} → обновление только заметок

Slide 12: Ключевая фича — Журнал и посещаемость (Журнал)

Реализовано: ✅ Календарная фильтрация событий, отметка посещаемости, синхронизация в реальном времени
- SquadLogFragment: Два RecyclerView (дети + события), MaterialAutoCompleteTextView выбор даты (±30 дней)
- Логика фильтра дат:
  - Будущая дата: события между [сегодня, выбранная]
  - Прошлая дата: события между [выбранная, сегодня]
  - Полное вхождение: event.timeFrom > left AND event.timeTo < right
- Поток посещаемости: Выбор события → загрузка посещаемости → переключение чекбоксов → POST /attendance → оптимистичное обновление UI с откатом при ошибке
- API Эндпоинты:
  - GET /events?limit=10 + фильтр по дате
  - GET /attendance?eventId={uuid}
  - POST /attendance {eventId, childId, isPresent}

Slide 13: Ключевая фича — Система уведомлений (Уведомления)

Реализовано: ✅ Список со статусами прочитано/непрочитано, индивидуальное и массовое "прочитано", иконки типов
- NotificationFragment: RecyclerView с иконками типов (метка карты, колокольчик, восклицание), относительное время
- Отображение времени: <1мин → секунды, <1ч → минуты, <1дня → часы, <30дней → дни, ≥30дней → дд.ММ.гггг
- UI States: Непрочитано = синий фон + левая граница, Прочитано = белый
- API Эндпоинты:
  - GET /notifications?limit=20
  - POST /notifications/read-notif {notifId}
  - POST /notifications/read-all

Slide 14: Ключевая фича — Управление профилем (Профиль)

Реализовано: ✅ Редактируемые поля с валидацией, форматирование телефона, выход
- ProfileFragment: CircleImageView аватар, отображение роли (маппинг из enum), название отряда из кэша
- Валидация:
  - Email: regex Patterns.EMAIL_ADDRESS
  - Телефон: Кастомный PhoneTextWatcher с маской +7 (xxx) xxx-xx-xx
  - Имя: Обязательное, непустое
- DataEditWaitButton: Неактивен до появления валидных изменений
- API Эндпоинты:
  - GET /users/profile
  - PUT /users/profile {fullName, email, phoneNumber}

Slide 15: Карта и будущие фичи (Карта)

Статус: 🔄 Планируется / В разработке
- Требования: Отслеживание геолокации детей в реальном времени через WebSocket (socket.io)
- Текущее: MapFragment — базовая структура-заглушка
- Точки интеграции WebSocket (проектированы, не реализованы):
  - Уведомления: Push в реальном времени при действиях senior/director
  - Карта: Живые обновления координат (lat/long) по интервалу или при изменении
  - Чат: Групповые сообщения (MVP: одна комната, Full: каналы по отрядам)
- Архитектура готова: Паттерн интерцептора ApiProvider поддерживает WebSocket upgrade

Slide 16: Качество кода и Developer Experience

- Repository Pattern (Android): Чистое разделение, тестируемость, единственная ответственность
- Generated API Client: Типобезопасная сеть из OpenAPI spec (OpenAPI Generator 7.10)
- Обработка ошибок: Паттерн DataCallback, try/catch в фоновых потоках, понятные тосты
- Состояния загрузки: ProgressBar + overlay, отключение RecyclerView во время запросов
- Валидация ввода: И клиентская (TextWatcher), и серверная (validation middleware)
- Логирование: Серверные actionLogs для всех CUD операций (цепочка middleware)
- Организация кода: Модульные роутеры, общий middleware, утилиты

Slide 18: Выводы и план развития

Ключевые технические решения:
- Паттерн hide/show фрагментов сохраняет состояние (вместо replace)
- SharedPreferences кэширование даёт offline-first UX
- OpenAPI-generated client убирает ручной маппинг DTO
- Ролевая middleware цепочка сохраняет роутеры чистыми

Roadmap:
1. Ближайшее: Экраны старшего вожатого (управление отрядами, логи, заявки)
2. Краткосрочное: Панель статистики директора, WebSocket для уведомлений
3. Среднесрочное: Карта с живыми локациями, система чата
4. Долгосрочное: Push-уведомления (FCM), очередь офлайн-синхронизации, мульти-лагерей
